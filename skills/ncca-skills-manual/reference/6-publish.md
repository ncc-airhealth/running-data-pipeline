## 6-1. 산출물 및 링크 검토

배포 전 전체 매뉴얼의 일관성과 링크를 최종 점검해요.

- `SKILL.md`에서 시작해 모든 세부 작업 문서와 지식 문서의 링크가 깨짐 없이 연결되는지 확인하세요.
- 새로 추가한 지식 문서가 `reference/knowledge/index.md`에 빠짐없이 등록되었는지 확인하세요.
- [글쓰기 규칙](./knowledge/writing-style.md)에 따라 문체(해요체/하세요체/~할 것)와 표준어('매뉴얼')가 지켜졌는지 확인하세요.

## 6-2. Git 변경 사항 확인

저장소 상태를 확인하고 배포에 포함할 파일만 선별해요.

```bash
git status -s
git diff
```

- 작업 중 생성된 임시 파일이나 의도치 않은 변경 사항이 없는지 확인하세요.
- `.gitignore`에 등록되지 않은 불필요한 시스템 파일이 포함되지 않도록 주의하세요.

## 6-3. 커밋 및 푸시

검토가 완료된 매뉴얼을 Git 저장소에 반영해요.

1. 배포할 매뉴얼 파일들을 스테이징하세요.
   ```bash
   git add skills/<매뉴얼-별칭>/
   ```
2. 작업 내용을 명확히 드러내는 커밋 메시지와 함께 커밋하세요.
   ```bash
   git commit -m "docs: <매뉴얼 이름> 작업 매뉴얼 추가"
   ```
3. 원격 저장소에 푸시하세요.
   ```bash
   git push origin <브랜치명>
   ```

## 완료 조건

다음 조건을 모두 만족하면 매뉴얼 검토와 배포가 완료돼요.

- [ ] `SKILL.md` 및 세부 문서 간의 상대 경로 링크가 모두 정상 동작함
- [ ] 신규 지식 문서가 `reference/knowledge/index.md`에 등록됨
- [ ] [글쓰기 규칙](./knowledge/writing-style.md)을 준수함
- [ ] 불필요한 임시 파일 없이 배포 대상 파일만 커밋됨
- [ ] 원격 저장소에 정상적으로 푸시(Push)가 완료됨

> **AI 추가 지침**
>
> 1. 링크 깨짐이나 문서 누락 여부를 먼저 점검하고 사용자에게 보고할 것
> 2. `git commit` 및 `git push`를 수행하기 전, 변경 파일 목록과 커밋 메시지를 사용자에게 제시하고 **반드시 사용자의 명시적 승인을 받을 것**
