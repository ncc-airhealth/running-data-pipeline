## 1-1. 목표 정의하기

매뉴얼로 만들고자 하는 작업의 **정의**, **목표**, **완료 기준**을 각각 명확히 정리해요.

- **작업 정의**: 어떤 작업을 수행하는지 한 문장으로 정의해요.  
  (예: "냄비와 가스레인지를 이용해 라면 1봉지를 끓이는 작업")
- **작업 목표**: 이 작업을 통해 달성하려는 결과나 목적을 정의해요.  
  (예: "면이 불지 않고 꼬들꼬들하게 잘 익은 라면 1그릇 완성")
- **완료 기준**: 작업이 성공적으로 끝났음을 검증할 수 있는 객관적인 기준을 정의해요.  
  (예: "정량의 국물과 알맞게 익은 면이 담긴 그릇이 식탁 위에 놓임")

> **AI 추가 지침:** 사용자에게 작업의 정의, 목표, 그리고 작업 완료를 판단할 수 있는 구체적인 기준(산출물, 검증 방법)을 질문할 것

## 1-2. 제목과 별칭 결정하기

[1-1](#1-1-목표-정의하기)에서 제시한 작업의 정의와 목표를 바탕으로 작업 매뉴얼의 제목("xxxx 매뉴얼")을 정해요. (예: "라면 조리 매뉴얼")
그리고 매뉴얼의 [kebab-case](https://stringcase.org/cases/kebab/) 별칭도 결정해주세요. 

> [!TIP] 별칭 네이밍 규칙
> 프로젝트의 일관성을 위해 별칭은 특별한 이유가 없다면 `ncca-<업무명>-manual` 형식을 권장해요.  
> (예: `ncca-cook-ramen-manual`)

> **AI 추가 지침:** 사용자에게 프로젝트 네이밍 규칙에 맞는 적절한 제목과 별칭을 제안할 것

## 1-3. 경로 구성하기

아래와 같이 현재 레포지토리에 매뉴얼(스킬) 경로를 구성해주세요.

```
running-data-pipeline/
├─── skills/
│    ├─── ncca-skills-manual/
│    ├─── <매뉴얼 별칭>/
│    │    ├─── reference/         # 문서
│    │    │   └─── knowledge/     # 지식
│    │    │        └─── index.md  # 지식 인덱스
│    │    └─── SKILL.md           # 개요
│    └─── ...
├─── .gitignore
└─── README.md
```
