# 6. 검토 및 배포

산출물 데이터, 메타데이터(`collection.json`), 설명 문서(`README.md`)를 최종 점검하고 원격 저장소에 배포해요.

## 세부 절차

1. 이전 단계 완료 상태 및 문서 일관성을 확인하세요.  
    실제 데이터 파일, `data/collection.json`, `README.md`의 내용(데이터셋 이름, 공간·시간 범위, 스키마, 출처/라이선스)이 서로 일치하는지 최종 대조하세요.

    > [!NOTE]
    >
    > 4단계 이후 데이터나 `collection.json`을 수정한 경우, `scripts/review.py`를 다시 실행하세요.

2. 대용량 파일 추적 설정을 확인하세요.  
   10MB 이상의 대용량 데이터 파일(Parquet, GeoTIFF, CSV 등)이 `.gitattributes`에 등록되어 있는지 확인하세요.
     ```bash
     git xet track "*.parquet"
     git check-attr filter -- "data/<file>"
     ```
    > [!TIP]
    >
    > `git check-attr` 결과에 `filter` 속성이 지정되어 있어야 대용량 파일로 안전하게 관리돼요.

3. 배포 파일을 선별하고 `git stage` 하세요.  

    > [!NOTE]
    >
    >  배포에 불필요한 임시 파일, 캐시, 개인 키나 API 토큰 등 민감 정보가 포함되지 않도록 확인하세요.

4. 커밋하고 원격 저장소에 푸시하세요.  
    작업 내용을 명확히 드러내는 커밋 메시지를 작성하고 푸시하세요.

    ```bash
    git add .
    git commit -m "feat: <데이터셋 이름> 데이터셋 구축"
    git push origin main
    ```

5. 원격 저장소 상태를 확인하세요.
   - 원격 저장소 페이지에 접속해 커밋 이력, 파일 목록, `README.md` 렌더링 상태를 확인하세요.

## 완료 조건

다음 조건을 모두 만족하면 검토와 배포가 끝나요.

- [ ] 데이터, 메타데이터, 설명 문서 간의 내용이 일치하고 검증을 통과함
- [ ] 대용량 파일이 `.gitattributes`로 정상 추적됨
- [ ] 민감 정보나 임시 파일 없이 배포 대상 파일만 커밋됨
- [ ] 원격 저장소에 변경 사항이 푸시되어 정상 반영됨

> **AI 추가 지침**
>
> 1. `git commit` 및 `git push`를 실행하기 전, 변경 파일 목록과 커밋 메시지를 사용자에게 제시하고 반드시 명시적 승인을 받을 것
> 2. 원격 저장소 푸시 완료를 확인하기 전에는 배포를 완료로 판단하지 말 것
