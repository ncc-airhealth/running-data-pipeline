# 3. 데이터 수집·처리 파이프라인 구성

[내부 처리 의존성 금지 원칙](./knowledge/repo-rules.md)에 따라, 구축하려는 저장소의 성격(원천 데이터셋 vs 가공 데이터셋)에 맞는 한 가지 방식을 선택하여 데이터를 준비해요.

> [!IMPORTANT] 단일 저장소 내 가공 의존성 금지
> 한 저장소 안에 원천 데이터를 저장해 두고, 같은 저장소 안에서 이를 읽어 가공 데이터를 생성하지 마세요. 가공 데이터셋은 반드시 별도 저장소로 분리하고 원천 저장소를 외부 참조해야 해요.

## 세부 절차

구축하려는 저장소의 유형에 따라 **A안** 또는 **B안** 중 하나를 선택하세요.

### A안. 원천 데이터 저장소 구축 (외부에서 데이터 획득)

외부 기관이나 공공데이터 포털 등에서 원본 데이터를 들여와 보관하는 저장소예요.

1. 원천 데이터를 확보하여 `data/` 폴더에 배치하세요.
   - **수동 다운로드 (API 미지원 공공데이터 등)**:
     - 포털 웹사이트에서 직접 신청하거나 파일을 내려받아 `data/`에 넣으세요.
     - 다른 팀원이 동일하게 재현할 수 있도록 **제공 기관, 신청/다운로드 URL, 신청 절차, 취득 일시**를 메모해 두세요. (5단계 `README.md`에 기록해요)
   - **자동 다운로드 (API/스크립트 지원 시)**:
     - [수집 코드 예시](../assets/data-extraction-example.py)를 참고해 `scripts/process.py`를 작성하고 실행해 `data/`에 원본을 내려받으세요.
2. 원본 데이터는 원본의 값, 정밀도, 좌표계를 임의로 변경하지 않고 보관하세요.

---

### B안. 가공 데이터 저장소 구축 (기존 저장소 데이터 가공)

이미 구축된 다른 데이터셋 저장소의 데이터를 입력으로 받아 정제·변환하는 저장소예요.

1. 가공 스크립트(`scripts/process.py`)를 작성하세요.
   - [처리 코드 예시](../assets/data-processing-example.py)를 참고하세요.
   - 외부 원천 저장소의 네임스페이스, 저장소 이름, 그리고 **특정 버전(커밋 SHA)**을 명시하여 소스 데이터를 불러오세요.
   - 가공 로직을 거쳐 최종 산출물만 현재 저장소의 `data/` 폴더에 저장하세요.
2. 스크립트 상단에 [PEP 723](https://peps.python.org/pep-0723/) 형식으로 의존성 패키지를 명시하세요.
3. `uv`로 의존성을 잠그고 실행하세요.
   ```bash
   uv lock --script scripts/process.py
   uv run --frozen --script scripts/process.py
   ```

## 완료 조건

다음 조건을 모두 만족하면 데이터 준비가 끝나요.

- [ ] 저장소 유형(원천 데이터 vs 가공 데이터)이 명확히 구분됨
- [ ] **원천 저장소인 경우**: 원천 데이터가 `data/`에 배치되고, 수동 취득 시 취득 경로/절차가 메모됨
- [ ] **가공 저장소인 경우**: 원천 저장소의 커밋 SHA를 참조하는 `scripts/process.py`와 `.lock` 파일이 존재하고, 실행 시 재현 가능한 산출물이 `data/`에 생성됨
- [ ] 동일 저장소 내에서 데이터를 읽어 다른 데이터로 가공하는 내부 의존성이 없음

> **AI 추가 지침**
>
> - 원천 데이터가 수동 다운로드 대상일 경우 사용자에게 신청 경로와 수령 절차를 질문하여 취득 이력을 정리할 것
> - 가공 데이터 저장소일 경우 참조할 원천 저장소 이름과 커밋 SHA를 사용자에게 확인할 것
> - `README.md`나 메타데이터만 수정할 때는 `scripts/process.py`를 불필요하게 다시 실행하지 말 것
