# 5. 저장소 설명 문서 작성

누구나 저장소의 데이터를 올바르게 이해하고 활용할 수 있도록 저장소 루트의 `README.md`를 작성해요.

## 세부 절차

1. 설명 문서 템플릿을 준비하세요.
   - [데이터 설명 문서 작성 규칙](./knowledge/technical-writing.md)을 확인하세요.
   - [Dataset Card 템플릿](../assets/dataset-card-template.md)을 복사해 저장소 루트에 `README.md` 파일을 만드세요.
     ```bash
     cp skills/ncca-datarepo-manual/assets/dataset-card-template.md README.md
     ```

2. 데이터 개요와 스키마를 작성하세요.
   - **소개**: 데이터가 무엇이며 왜 만들어졌는지 한두 문장으로 요약하세요.
   - **공간·시간 범위**: 실제 데이터의 지리적 영역(지역명)과 수집 기간을 기입하세요.
   - **데이터 구성 및 필드 명세**: 4단계 `collection.json`에서 정의한 메타데이터(table 또는 raster/eo 확장 정보)를 참고하여, 데이터 파일 형식과 각 컬럼(또는 래스터 밴드)의 자료형, 단위, 유효 범위를 표로 정리하세요.

3. 데이터 획득·처리 이력을 기록하세요.
   - **원천 저장소인 경우**: 수동 다운로드 경로(제공 기관, 신청/다운로드 URL, 신청 절차, 취득 시점) 또는 자동 수집 방법을 누구나 따라 할 수 있게 구체적으로 적으세요.
   - **가공 저장소인 경우**: 참조한 원천 저장소와 함께, 어떤 전처리 및 정제 규칙을 거쳐 산출물을 생성했는지 가공 방법을 자연어로 이해하기 쉽게 설명하세요.

4. 출처와 라이선스를 명시하세요.
   - 원천 출처와 데이터 제공 기관, 공식 라이선스를 명시하세요.

## 완료 조건

다음 조건을 모두 만족하면 설명 문서 작성이 끝나요.

- [ ] 저장소 루트에 `README.md` 파일이 존재함
- [ ] 실제 데이터, `data/collection.json`, `README.md`의 내용(이름, 범위, 스키마, 라이선스)이 서로 일치함
- [ ] 데이터 스키마와 획득·가공 방법이 자연어로 명확히 설명됨
- [ ] 템플릿 치환자(`{{ ... }}`)나 가이드 주석(`<!-- ... -->`)이 남아 있지 않음

> **AI 추가 지침:** 확인되지 않은 출처나 가공 규칙을 임의로 추측하지 말고 사용자에게 확인하여 작성할 것
