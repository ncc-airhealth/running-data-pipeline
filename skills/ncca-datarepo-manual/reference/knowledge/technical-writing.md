# 데이터 설명 문서 작성 규칙

신규 팀원을 비롯한 사용자가 데이터를 올바르게 이해하고 즉시 활용할 수 있도록 작성하는 기술 문서 작성 규칙이에요.

## 1. 문체와 문장 원칙

- **해요체와 하세요체**: 설명 본문은 해요체(`~해요`, `~있어요`), 독자에게 작업을 안내할 때는 하세요체(`~하세요`, `~해주세요`)를 사용해요.
- **단문 작성**: 한 문장에는 하나의 정보나 행동만 담아요. 문장이 길어지면 마침표로 나누세요.
- **주어와 능동형**: 독자가 수행할 작업은 독자를 주어로 능동형으로 작성하세요. 파이프라인이나 도구의 동작을 설명할 때만 해당 도구를 주어로 써요.
- **구체적인 사실과 수치**: 모호한 수식어 대신 확인된 수치, 범위, 단위, 조건을 명확히 밝혀요.
  - "파일 크기가 매우 큽니다" (X) ➔ "단일 파일 크기가 약 4.2GB입니다" (O)

## 2. 용어와 표기 기준

- **기술 용어 표준화**: 공식 문서 표기를 따르고 문서 전체에서 같은 용어를 일관되게 써요.
- **명칭 표기**:
  - `product`는 '제품' 대신 `프로덕트`로 표기해요.
  - 모호한 번역어 대신 `버전`, `커밋 SHA`, `브랜치`, `태그` 등 명확한 Git/데이터 용어를 사용해요.
  - 약어는 처음 등장할 때 전체 명칭(예: STAC, SpatioTemporal Asset Catalog)과 함께 작성해요.

## 3. Dataset Card (`README.md`) 작성 지침

- **개요 직행**: 첫 문단에서 데이터의 핵심 내용, 생성 목적, 공간 및 시간 범위를 바로 설명해요.
- **데이터 스키마 명시**: 테이블 데이터는 열(Column) 목록과 단위, 래스터 데이터는 밴드(Band) 정보를 표 형식으로 정리해요.
- **데이터 조회 및 갱신 방법**: 신규 팀원이 데이터를 파이썬(Polars, Pandas 등)으로 바로 불러오는 코드 스니펫과, 필요 시 데이터를 갱신하는 명령어를 예제로 제공해요.

## 4. 코드 주석과 docstring

- 스크립트(`scripts/process.py` 등)의 주석과 docstring은 짧고 자연스러운 한국어로 작성해요.
- 코드 자체로 알 수 있는 단순 동작을 반복하지 말고, **가공 규칙, 알고리즘 선택 배경, 제약 조건**을 설명하세요.
