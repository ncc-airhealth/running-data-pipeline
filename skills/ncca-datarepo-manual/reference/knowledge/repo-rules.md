# 데이터 저장소 운영 및 구성 규칙

팀 내부의 데이터를 안전하고 체계적으로 관리하기 위해 저장소를 생성하고 구성할 때 반드시 준수해야 하는 규칙이에요.

## 1. 저장소 명명 및 권한 규칙

### 저장소 이름 (kebab-case)
- 데이터셋 저장소 이름은 소문자와 하이픈(`-`)만 사용하는 kebab-case 형식을 따라요.
- 데이터의 성격, 주제 또는 대상 영역을 명확히 드러내도록 작성하세요.
  - 좋은 예: `seoul-air-quality-2023`, `korea-temperature-grid`
  - 피해야 할 예: `myData`, `test_data_final`, `temp123`

### 기본 권한: 비공개 (Private)
- 새로 생성하는 저장소의 공개 범위는 특별한 승인이 없는 한 항상 `private`으로 설정해요.
- 팀 외부에 데이터를 공개(`public`)할 때는 팀 담당자의 명시적인 승인과 검토를 거친 후 전환하세요.

## 2. 데이터셋 내부 처리 의존성 금지 원칙

데이터셋의 재현성과 독립성을 보장하기 위해 저장소 내부의 상호 의존을 엄격히 금지해요.

- **원칙**: 동일 저장소 안에서 특정 데이터를 입력으로 받아 다른 데이터를 가공·생성하는 내부 처리 파이프라인을 두지 않아요.
- **적용**: 기존 데이터셋을 가공해 새로운 산출물을 만들 때는 반드시 **새로운 별도 저장소**를 생성하고, 이전 저장소를 원천 데이터(Source Dataset)로 참조하세요.
- **이유**: 한 저장소 내에서 데이터 간의 처리 의존성이 얽히면 버전 추적, 캐싱, 데이터 재현이 매우 어려워져요.

## 3. 표준 디렉터리 구조

로컬 및 원격 저장소는 다음 표준 디렉터리 구조를 유지해요.

```
<저장소 루트>/
├── data/                  # 산출물 데이터 파일 (CSV, Parquet, GeoTIFF 등)
│   └── collection.json    # STAC Collection 메타데이터
├── scripts/               # 데이터 수집 및 처리 스크립트 (파이프라인 재현성)
│   ├── extract.py         # 원천 데이터 다운로드/추출 스크립트 (선택)
│   ├── process.py         # 데이터 전처리 및 변환 스크립트
│   └── review.py          # 데이터 및 메타데이터 무결성 검증 스크립트 (선택)
├── .gitignore             # Git 추적 제외 목록
└── README.md              # Dataset Card (데이터 개요, 스키마, 사용법)
```

- **`data/`**: 최종 산출물 데이터와 STAC 메타데이터(`collection.json`)를 보관해요.
- **`scripts/`**: 누구나 데이터를 처음부터 다시 생성할 수 있도록 재현 가능한 독립 스크립트를 보관해요.
- **`README.md`**: 신규 팀원이 데이터를 조회하고 활용할 수 있는 상세 안내서 역할을 해요.
